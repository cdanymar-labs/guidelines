Guidelines
==========


Files
-----

Extensions
^^^^^^^^^^

.. list-table::
   :header-rows: 1

   * - Extension
     - Purpose
     - Notes
   * - ``.rst``
     - Documentation
     - Preferred over markdown files
   * - ``.md``
     - Documentation
     - Tolerated temporary for internal purposes
   * - ``.c``
     - C source
     -
   * - ``.h``
     - C header
     -
   * - ``.cpp``
     - C++ source
     -
   * - ``.hpp``
     - C++ header
     - It is best to avoid header files in C++
   * - ``.cppm``
     - C++ module
     -
   * - ``.cmake``
     - CMake script
     -


Special Files
^^^^^^^^^^^^^

.. list-table::
   :header-rows: 1

   * - File
     - Notes
   * - ``LICENSE``
     - Uppercase, no extension
   * - ``readme.md``
     - Lowercase
   * - ``changelog.md``
     - Lowercase


Development
-----------

Follow test-driven development.

Target modern C (C23/C26/C29/C2y) and C++ (C++23/C++26/C++29).


Commit Messages
---------------

Based on `cdanymar/commit-messages <https://github.com/cdanymar/commit-messages>`_, which follows `Conventional Commits 1.0.0 <https://www.conventionalcommits.org/>`_.


Format
^^^^^^

.. code-block:: text

    <type>(<scope>): <verb> <description>

    [optional body]

    [optional footer]


Types
^^^^^

.. list-table::

   * - Type
     - Purpose
   * - ``init``
     - Initial commit, might describe the copied template
   * - ``chore``
     - Routine maintenance with no production changes
   * - ``revert``
     - Revert of one of the previous commits
   * - ``feat``
     - Introduction of a new complete feature
   * - ``fix``
     - Bug fix
   * - ``docs``
     - Documentation
   * - ``style``
     - Formatting, whitespace, no logic change
   * - ``refactor``
     - Code restructure without new features or fixes
   * - ``perf``
     - Performance improvement
   * - ``test``
     - Tests
   * - ``build``
     - Build system and tooling changes
   * - ``ci``
     - Continuous integration and deployment pipeline
   * - ``merge``
     - Semi-automated merge commit message
   * - ``wip``
     - Work in progress emergency commit
   * - ``generated``
     - Commit generated by a tool


Scopes
^^^^^^

.. list-table::

   * - Scope
     - Covers
   * - ``api``
     - Public API
   * - ``bench``
     - Benchmarks
   * - ``cmake``
     - CMake build system
   * - ``config``
     - Environment configuration files
   * - ``core`` [#core]_
     - Central logic, but prefer explicit scope
   * - ``db``
     - Database
   * - ``deps``
     - Dependencies
   * - ``docker``
     - Docker, Docker Compose, maybe Kubernetes
   * - ``fuzz``
     - Fuzz testing
   * - ``legal``
     - License, notice, etc.
   * - ``linux``
     - Linux
   * - ``mac``
     - macOS
   * - ``mock``
     - Mock testing
   * - ``ui``
     - User interface
   * - ``win``
     - Windows

.. [#core] Last resort. Prefer a more specific scope.


Verbs
^^^^^

.. list-table::

   * - Verb
     - Use when
   * - ``add``
     - Adding a file, option, flag, dependency, etc.
   * - ``remove``
     - Removing a file, option, flag, dependency, etc.
   * - ``move``
     - Moving a file, function, or class without changing it
   * - ``implement``
     - Building logic, behavior, UI changes, or structural modifications
   * - ``bump`` [#bump]_
     - Updating a version number

.. [#bump] Reserved for version bumps only.
